# فروشگاه اینترنتی کالانو

فروشگاه اینترنتی فارسی و راست‌به‌چپ به سبک دیجی‌کالا، همراه با **سرور، پایگاه داده، پنل مدیریت، درگاه پرداخت زرین‌پال و ورود با پیامک کاوه‌نگار**.

- بدون هیچ پکیج خارجی: فقط Node.js نسخه ۲۲.۱۳ یا جدیدتر لازم است. پایگاه داده SQLite داخل خود Node است.
- سایت دو حالت دارد:
  - **حالت سرور:** با `npm start`. داده‌ها واقعی‌اند و از پنل مدیریت کنترل می‌شوند.
  - **حالت نمایشی:** فقط فایل‌های پوشه‌ی `public`، مثلاً روی GitHub Pages. با داده‌های نمونه و بدون سرور کار می‌کند.

---

## ۱. اجرا روی کامپیوتر خودتان

```bash
cd shop
npm start
```

- فروشگاه: <http://localhost:3000>
- پنل مدیریت: <http://localhost:3000/admin/> (رمز حالت توسعه: `admin1234`)

در حالت توسعه، وقتی کلیدهای زرین‌پال و کاوه‌نگار تنظیم نشده‌اند:
- **کد ورود** روی صفحه و در کنسول سرور نمایش داده می‌شود.
- **پرداخت اینترنتی** به یک درگاه شبیه‌سازی‌شده می‌رود که دو دکمه‌ی «پرداخت موفق» و «انصراف» دارد.

تست‌های خودکار سرور:

```bash
npm test
```

## ۲. پنل مدیریت

| بخش | کارها |
|---|---|
| داشبورد | فروش کل، سفارش‌های امروز، سفارش‌های آماده ارسال، نمودار فروش ۱۴ روز اخیر، کالاهای رو به اتمام |
| سفارش‌ها | فیلتر بر اساس وضعیت، جستجو با کد یا موبایل، تغییر وضعیت (در حال پردازش ← ارسال شده ← تحویل شده)، لغو و برگشت موجودی، دیدن آدرس و جزئیات |
| محصولات | افزودن، ویرایش، پنهان کردن و حذف کالا؛ بارگذاری عکس؛ رنگ‌ها و مشخصات فنی |
| دسته‌بندی‌ها | افزودن، ویرایش و حذف دسته و زیردسته |
| کدهای تخفیف | ساخت کد درصدی با سقف، فعال و غیرفعال کردن |
| دیدگاه‌ها | پنهان کردن یا حذف دیدگاه‌ها |
| مشتریان | لیست مشتریان با تعداد سفارش و مجموع خرید |
| تنظیمات فروشگاه | **نام فروشگاه، رنگ اصلی و رنگ مکمل**، تلفن پشتیبانی، هزینه‌های ارسال، حداقل خرید برای ارسال رایگان، سقف تعداد هر کالا |

## ۳. اتصال درگاه پرداخت و پیامک

فایل `.env.example` را با نام `.env` کپی کنید و پر کنید:

```bash
cp .env.example .env
```

### زرین‌پال
1. در [zarinpal.com](https://www.zarinpal.com) ثبت‌نام کنید و درگاه بگیرید. نیاز به اینماد دارد.
2. **مرچنت کد** را در `ZARINPAL_MERCHANT_ID` بگذارید.
3. `PUBLIC_URL` را آدرس واقعی سایت بگذارید، مثلاً `https://shop.example.ir`. زرین‌پال بعد از پرداخت به `PUBLIC_URL/api/pay/callback` برمی‌گردد.
4. برای آزمایش بدون پول واقعی: `ZARINPAL_SANDBOX=true`.

مبلغ همیشه در سرور و از روی پایگاه داده حساب می‌شود و پرداخت با API تأیید (verify) زرین‌پال بررسی می‌شود. پس مشتری نمی‌تواند قیمت را دست‌کاری کند یا پرداخت جعلی ثبت کند. سفارشی که ۳۰ دقیقه پرداخت نشود، خودکار لغو می‌شود و موجودی‌اش برمی‌گردد.

### کاوه‌نگار
1. در [kavenegar.com](https://kavenegar.com) ثبت‌نام کنید.
2. در بخش «ارسال سریع (Verify Lookup)» یک قالب بسازید که متن آن `%token` داشته باشد. مثال: `کد ورود شما به فروشگاه: %token`
3. کلید API را در `KAVENEGAR_API_KEY` و نام قالب را در `KAVENEGAR_TEMPLATE` بگذارید.

امنیت ورود:
- کد ۵ رقمی است و ۲ دقیقه اعتبار دارد.
- بعد از ۵ تلاش اشتباه باطل می‌شود.
- ارسال دوباره تا ۶۰ ثانیه ممکن نیست.

## ۴. انتشار روی اینترنت

### نسخه نمایشی رایگان: GitHub Pages
فایل `.github/workflows/shop-pages.yml` در هر push:
- تست‌های سرور را اجرا می‌کند.
- اگر روی شاخه‌ی پیش‌فرض مخزن باشد، پوشه‌ی `shop/public` را منتشر می‌کند.

فقط یک بار در گیت‌هاب: **Settings ← Pages ← Build and deployment ← Source = GitHub Actions**

آدرس سایت: `https://<نام-کاربری>.github.io/<نام-مخزن>/`

> GitHub Pages فقط فایل ثابت نمایش می‌دهد. پس سایت آنجا در **حالت نمایشی** است و پنل مدیریت و پرداخت واقعی ندارد.

### نسخه کامل با سرور
یکی از این راه‌ها:
- **هاست ابری ایرانی** (مثل لیارا یا هم‌روش) یا **سرور مجازی (VPS)**: پوشه‌ی `shop` را آپلود کنید، فایل `.env` را بسازید و `npm start` را اجرا کنید.
- **Docker:**
  ```bash
  docker build -t kalano-shop .
  docker run -d -p 3000:3000 --env-file .env -v kalano-data:/app/data kalano-shop
  ```

نکته‌های انتشار:
- پشت Nginx یا سرویس ابری، `TRUST_PROXY=true` بگذارید و HTTPS را فعال کنید.
- از پوشه‌ی `data` (پایگاه داده و عکس‌ها) مرتب نسخه پشتیبان بگیرید.

## ۵. ساختار پروژه

```
shop/
├── public/              فایل‌های سایت (برای GitHub Pages هم همین پوشه منتشر می‌شود)
│   ├── index.html
│   ├── css/style.css
│   ├── js/data.js       داده‌های نمونه و تنظیمات پیش‌فرض (منبع داده‌ی اولیه‌ی پایگاه داده هم هست)
│   ├── js/app.js        منطق فروشگاه؛ اگر سرور باشد به API وصل می‌شود، وگرنه حالت نمایشی
│   └── admin/           پنل مدیریت
├── server/
│   ├── index.js         شروع سرور
│   ├── app.js           API، ورود، سفارش، پرداخت، پنل مدیریت و سرو فایل‌ها
│   ├── db.js            پایگاه داده SQLite و داده‌ی اولیه
│   ├── payment.js       زرین‌پال
│   ├── sms.js           کاوه‌نگار
│   └── config.js        خواندن .env
├── test/api.test.js     تست‌های خودکار
├── .env.example
└── Dockerfile
```

## ۶. شخصی‌سازی سریع
- **نام، رنگ‌ها و هزینه ارسال:** از پنل مدیریت ← تنظیمات فروشگاه. برای حالت نمایشی، `settings` در `public/js/data.js`.
- **کالاها و دسته‌ها:** از پنل مدیریت. داده‌های اولیه در `public/js/data.js` هستند و فقط بار اول، وقتی پایگاه داده خالی است، وارد می‌شوند.
- **شروع از صفر:** پوشه‌ی `data` را پاک کنید تا پایگاه داده دوباره از داده‌های نمونه ساخته شود.
