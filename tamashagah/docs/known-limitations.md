# محدودیت‌های شناخته‌شده و کارهای نیازمند زیرساخت بیرونی

این فهرست عمداً صریح است: چه چیزی در این مخزن **کار می‌کند و تأیید شده**، چه چیزی **به سرویس یا اعتبارنامه‌ی بیرونی نیاز دارد**
(و در محیط توسعه قابل اجرا نبود)، و چه چیزی **پیاده‌سازی نشده**.

## ۱. نیازمند اعتبارنامه یا زیرساخت بیرونی (تأییدنشده در این محیط)

| مورد | وضعیت |
| --- | --- |
| **ایمیل واقعی (SMTP)** | ارسال از طریق SMTP با Mailpit تأیید شد. برای تولید، ارائه‌دهنده‌ی SMTP خودتان را در `.env.docker` بگذارید (`docs/deployment.md`). |
| **دامنه و گواهی TLS واقعی** | پروکسی Caddy با گواهی محلی تست شد (HTTP/2، HSTS، کوکی `__Host-`). صدور Let's Encrypt نیاز به دامنه‌ی عمومی دارد. |
| **ذخیره‌ساز S3 تجاری / CDN** | با RustFS (آزمون `pnpm check:storage`) و شبیه‌ساز S3 تست شد. AWS/آروان/لیارا را با همان دستور بسنجید. حالت `MEDIA_DELIVERY=redirect` به CORS سطل و قانون lifecycle برای multipart ناتمام نیاز دارد. |
| **پرداخت و تسویه (درآمدزایی)** | فقط **معماری** است (`docs/monetization-architecture.md`: دفتر کل، آیدمپوتنسی، وضعیت پرداخت، `NullBillingProvider`). هیچ پولی ساخته یا نمایش داده نمی‌شود؛ درگاه و ارائه‌دهنده‌ی پرداخت وصل نیست. |
| **اپلیکیشن‌های موبایل** | وجود ندارد. وب‌اپ PWA است (manifest، service worker، دکمه‌ی نصب)؛ صفحه‌ی `/apps` فروشگاه‌ها را فقط «به‌زودی» نشان می‌دهد. |
| **پخش H.264/AAC در مرورگر در sandbox** | Chromium همراه Playwright کدک اختصاصی ندارد. خروجی worker (H.264+AAC، HLS) با FFmpeg کامل decode و بررسی شد؛ پخش با hls.js روی VP9/Opus در مرورگر تأیید شد. روی Chrome/Safari/Firefox واقعی و iOS یک بار تست دستی کنید. |
| **ساخت تصویر worker با `apt-get install ffmpeg`** | مخزن Debian در sandbox مسدود بود (با ffmpeg ایستا جایگزین شد). دستور استاندارد است و در CI (`compose-smoke`) روی GitHub اجرا می‌شود. |
| **CI روی GitHub** | workflow نوشته شده؛ نتیجه‌ی اجرای کامل روی GitHub را خودتان ببینید. |

## ۲. محدودیت‌های محصول (آگاهانه یا باقی‌مانده)

* **پیشنهاددهی** قاعده‌محور و شفاف است (وزن‌ها در `docs/features/discovery.md`)؛ یادگیری ماشین ندارد. «داغ‌ترین‌ها» از یک استخر محدود (۳۰۰ پرمخاطب + ۲۰۰ جدید) انتخاب می‌شود؛ ویدیوهای کم‌بازدیدِ بیرون استخر در رتبه‌بندی داغ دیده نمی‌شوند.
* **بازدید و زمان تماشا**: ضدسوءاستفاده‌ی پایه دارد (آستانه‌ی پخش، حذف تکراری ۳۰ دقیقه‌ای، فیلتر ربات‌های آشکار، محدودسازی نرخ، سقف زمان تماشا بر اساس ساعت واقعی)، اما مقابل اسکریپتِ مصمم مقاوم نیست؛ برای پول واقعی به توکن پخش امضاشده و تشخیص ناهنجاری نیاز است.
* **ویدیو**: HLS با بخش‌های MPEG-TS و نردبان ۱۰۸۰/۷۲۰/۴۸۰/۳۶۰ (هرگز بزرگ‌تر از منبع نمی‌شود). نه پخش زنده، نه DRM، نه زیرنویس خودکار (زیرنویس VTT قابل بارگذاری است)، نه DASH/AV1.
* **جست‌وجو**: PostgreSQL FTS با پیکربندی `simple` + نرمال‌سازی فارسی + trigram؛ ریشه‌یابی فارسی (stemming) ندارد. تغییر نام کانال، `searchBody` ویدیوها را بازنمایه نمی‌کند.
* **تحلیل**: رویدادهای first-party؛ بدون جغرافیا؛ «منبع ترافیک» فقط میزبان referrer است؛ لایک/دیدگاه به‌صورت نمونه ساخته نمی‌شود؛ شمارش ریزش/دنبال‌کردن به تفکیک ویدیو وجود ندارد.
* **اعلان ایمیلی**: ترجیح `notifyByEmail` ذخیره می‌شود اما فرستنده‌ی ایمیل اعلان‌ها پیاده‌سازی نشده (فقط ایمیل‌های تأیید و بازیابی).
* **حساب**: بدون احراز دو مرحله‌ای، بدون ورود اجتماعی، بدون حذف حساب/خروجی داده‌ی کاربر.
* **مدیریت محتوا**: دستی (گزارش، ناظر، مدیر)؛ تشخیص خودکار محتوای ممنوعه یا اثرانگشت کپی‌رایت ندارد. پس از takedown تا ۱۰ ثانیه فایل‌های کش‌شده‌ی `/media` در دسترس می‌مانند.
* **امنیت**: CSP برای `script-src` به `'unsafe-inline'` نیاز دارد (Next.js بدون nonce).
* **صفحه‌های حقوقی** (`/terms`، `/privacy`، `/copyright`) قالب‌اند؛ پیش از انتشار با وکیل بازبینی شوند. نشانی تماس امنیتی (`security.txt`) را اپراتور تعیین می‌کند.
* **صفحه‌ی «پیدا نشد» در مسیرهایی با `loading.tsx`** هنگام استریم، کد HTTP 200 دارد (ربات‌ها 404 می‌گیرند؛ وجود منبع فاش نمی‌شود).
* **مقیاس**: تک‌منطقه؛ شمارنده‌ها denormalized هستند و worker هر شب ساعت ۳:۳۰ (وقت تهران) آن‌ها را هم‌تراز می‌کند. اندازه‌گیری‌ها: ۱۲ هزار ویدیو و ۱٫۵ میلیون رویداد → صفحات فهرست زیر ۱۰۰ms گرم؛ تحلیل ۲۰۰ هزار رویداد: ۳۰ روز ≈ ۲۶۰ms، ۳۶۵ روز ≈ ۷۸۰ms.
* **یافته‌های بازبینی مستقل که عمداً رفع نشدند** (ریسک کم/متوسط، در `docs/security.md` §13):
  * با `TRUSTED_PROXY_HOPS=0` (پیش‌فرض Compose بدون پروکسی) IP کاربر نامعلوم است و ورود/ثبت‌نام/بازیابی یک سطل مشترک دارند؛ یک مهاجم می‌تواند سقف آن را پر کند. در تولید همیشه از overlay پروکسی (`TRUSTED_PROXY_HOPS=1`) استفاده کنید.
  * سهمیه‌ی روزانه‌ی بارگذاری از ردیف‌های موجود شمرده می‌شود؛ حذف ویدیو آن را آزاد می‌کند (سقف ساعتی ۲۰ بارگذاری برقرار است).
  * ثبت‌نام وجود قبلی یک ایمیل را فاش می‌کند (ورود و بازیابی فاش نمی‌کنند).
  * پاسخ هم‌زمان با حذف ریشه‌ی دیدگاه ممکن است شمارنده را موقتاً ناهم‌تراز کند؛ job شبانه اصلاح می‌کند.
* **Prettier** اجباری نشده (ESLint و TypeScript اجباری‌اند).

## ۳. داده‌ی نمونه

`pnpm seed:demo` حساب‌ها، کانال‌ها، ۵۰ ویدیوی واقعاً قابل‌پخش (HLS)، ویدیوهای عبوری از pipeline واقعی و رویدادهای بازدید می‌سازد. همه‌ی رویدادهای مصنوعی `source = 'SEED'` دارند، در رابط «نمونه» نشان داده می‌شوند و در شرایط درآمدزایی حساب نمی‌شوند.
**روی پایگاه داده‌ی تولید اجرا نکنید** (حساب‌های `*@tamashagah.test` می‌سازد).
